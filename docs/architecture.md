# معماری

## نمای کلی

```
Telegram ──webhook──▶ webhook.php ──▶ Bot (lib/Bot*.php) ──▶ Repo / Plan ──▶ MySQL
Mini App ──fetch───▶ api.php     ──▶ Api (lib/Api.php)  ──┘
cPanel Cron ───────▶ cron.php    ──▶ Reminders / IncomeReminders / Backup
```

همه چیز PHP خالص (بدون Composer) است تا روی هر هاست اشتراکی اجرا شود.

## فایل‌ها

| فایل | نقش |
|---|---|
| `lib/core.php` | بارگذاری config، اتصال PDO، کلاینت API تلگرام (`TG`)، تقویم شمسی (`J`)، ابزارها (`U`) |
| `lib/schema.sql` | جداول پایه |
| `lib/Income.php` | `Migrate` (ارتقای خودکار جداول)، `Plan` (الگوریتم تخصیص)، صفحه‌های درآمد در ربات |
| `lib/IncomeStats.php` | واریزها (`Deposit`)، پرسش «واریز شد؟»، آمار و پیش‌بینی درآمد |
| `lib/Repo.php` | دسترسی به داده: کاربران، دسته‌ها، تعهدات، سررسیدها، پرداخت‌ها، بودجه |
| `lib/Bot.php` + `BotWizard.php` + `BotPanels.php` | هندلر پیام‌ها و دکمه‌ها، ویزارد افزودن، تنظیمات، دسته‌ها، مدیریت |
| `lib/Reports.php` | گزارش‌های ربات و نویسنده XLSX بدون وابستگی |
| `lib/Jobs.php` | یادآوری‌ها، خلاصه ماه، بکاپ |
| `lib/Api.php` | API مینی‌اپ و احراز هویت `initData` |

## داده‌ها

| جدول | محتوا |
|---|---|
| `users` | کاربران، دسترسی، تنظیمات یادآوری، حالت تخصیص، وضعیت گفتگو (state) |
| `categories` | دسته‌های هر کاربر و سقف بودجه |
| `obligations` | تعهدات: `loan` / `recurring` / `once`، دوره، مالک، کاربر مشترک و درصد سهم |
| `dues` | سررسیدها (هر قسط/دوره)، مبلغ، پرداخت‌شده، وضعیت |
| `payments` | هر پرداخت (امکان پرداخت جزئی و لغو) |
| `incomes` / `income_overrides` | درآمدهای ثابت و مبلغ واقعی هر ماه |
| `alloc_map` | تخصیص دستی تعهد ← درآمد (برای هر کاربر جدا) |
| `deposits` / `set_aside` | ثبت واریز و «کنار گذاشتم» برای هر درآمد در هر ماه |
| `reminder_log` / `income_log` / `budget_alerts` | جلوگیری از ارسال تکراری |
| `settings` | تنظیمات داخلی (نسخه schema، آخرین کرون، …) |

- تاریخ‌ها در دیتابیس **میلادی** (`DATE`) ذخیره و در نمایش به شمسی تبدیل می‌شوند؛ اقساط ماهانه بر اساس **ماه شمسی** ساخته می‌شوند (روز ۳۱ در ماه‌های ۳۰ روزه به آخر ماه می‌افتد).
- سررسیدهای پرداخت‌های دوره‌ای به‌صورت تنبل تا حدود ۲۰۰ روز جلوتر ساخته می‌شوند.
- سهم هر کاربر از تعهد مشترک: مالک `owner_share`٪ و طرف مقابل باقی آن.

## الگوریتم تخصیص (`Plan::compute`)

برای ماه M، واریزهای هر درآمد در ماه‌های M-2 تا M+1 و سررسیدهای M-1 تا M+1 بررسی می‌شوند:

1. **تخصیص دستی**: هر سررسیدِ تعهدِ متصل، به آخرین واریزِ همان درآمد که تاریخش ≤ سررسید است.
2. **تخصیص خودکار** (فقط در حالت خودکار): برای بقیه، از بین آخرین واریز هر درآمد قبل از سررسید، جدیدترینی که هنوز ظرفیت دارد؛ اگر هیچ‌کدام ظرفیت نداشت، آنکه بیشترین فضای خالی را دارد.
3. خروجی: واریزهای ماه M با اقساط متصل، اقساط ماه M که از واریزهای ماه قبل پوشش داده شده‌اند، و اقساط بدون منبع.

«آزادِ واقعی ماه» = جمع دریافتی‌های ماه − جمع تخصیص‌ها − اقساط بدون منبع.

## کرون (`cron.php`، هر ۱۵ دقیقه)
1. ساخت سررسیدهای جدید پرداخت‌های دوره‌ای
2. برای هر کاربر، اگر به ساعت یادآوری‌اش رسیده‌ایم و امروز ارسال نشده: یادآوری سررسیدها و معوقه‌ها
3. پرسش «واریز شد؟» (یک بار در روز، تا ۱۰ روز بعد از موعد)
4. خلاصه ماه در سه روز اول هر ماه
5. بکاپ روزانه (`backups/`، ارسال برای مدیر) و پاک‌سازی لاگ‌ها و فایل‌های موقت
